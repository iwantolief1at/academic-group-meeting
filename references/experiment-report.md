# 实验模式

按“问题 → 假设 → 对照设计 → 结果 → 分析 → 下一步”组织。章节可选：概览，上次任务，研究问题，环境设置，Baseline/改进，实验设计，核心结果，可视化/Bad Case，当前问题，阶段结论，后续计划，导师讨论点。

建立 run 对照：run_id、代码提交（已知时）、配置/日志路径、数据划分、输入大小、训练预算、种子、评估脚本版本、硬件、指标定义。明确日志证实的配置与仅存在配置文件中的参数。缺少配置、日志或结果时标明缺口；不编造 GPU、batch、学习率、训练次数。

先检查对照是否可比。消融须说明固定条件和唯一改动；多项同时改变只能描述观察到的关联。多种子才能报告相应的均值/标准差；单次实验不能编造误差条。失败、下降、缺失值同样展示，不只挑最优 run。

结果页须给明确结论以及边界。使用 AP、AP50、AP_small 等指标时沿用实际评估定义；遥感项目的小目标阈值不自动等同 COCO 定义。速度对比需硬件、batch、输入大小、预热、同步与后处理条件。阈值/置信度/IoU 改动不能混入“网络改进”解释。

检测对比使用同一图像、相同裁剪区域、缩放和阈值；图例区分 GT、预测、漏检与误检。Bad Case 列出 sample_id、失败现象、证据、可能原因和可验证下一步，不能从一张图断言因果。保留代表性采样原则，禁止仅展示有利样本。

每项实验显示“已完成 / 进行中 / 计划”；未完成结果不画成已测曲线。计划写验证目标、固定条件、停止/成功标准与待讨论决策。更新旧报告时保留 slide_id、历史结果和来源，标注本周新增证据。
